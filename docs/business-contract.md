# 业务契约

所有处理均验证租户、店铺、客户、订单与订单行关系。人工方案必须引用当前适用规则。每版方案不可原地覆盖；客户选择与审批绑定内容摘要。审批记录追加保存，撤回不会删除历史。动作稳定 ID 对应一个方案；换 ID 会返回同一原动作，换方案仍检查订单行剩余权益。

| 分支 | 执行条件 | 合成动作与后续证据 | 关闭条件 |
|---|---|---|---|
| 破损补发 | 订单行、数量、适用政策、选择、批准、库存 | 预留 → 受理 → 出库 → 送达 | 动作终态 + 客户解决确认 + 客服结案 |
| 退款 | 币种、正整数金额、剩余权益和资金额度 | 占用处理中金额 → 受理 → 成功或失败 → 台账结转 | 支付终态与客户解决确认 |
| 退货 | 范围、方案与授权 | 授权受理 → 收货 → 质检 | 后续处理另建有授权动作，客户确认 |
| 未收到货/物流异常 | 原订单记录与客户陈述分开 | 查询短路径，或授权调查 → 调查结论 | 调查不自动证明问题解决 |
| 少件 | 订单数量、实收材料与剩余权益 | 补齐复用库存预留与履约 | 客户确认实际收到 |
| 错件 | 原商品和错误范围 | 补发/退货/退款方案复用统一边界 | 实际后续处理与客户确认 |
| 取消 | 订单仍在 paid/processing，授权生效 | 受理后再次核对阶段 → 取消回执 | 资金退款另走统一动作，不假称已退 |
| 改址 | 完整新地址、原单未出库 | 原地址先保留，成功回执后更新 | 不能仅改本地字段宣称承运方已接受 |

运行、工单、动作状态分开。动作 accepted 只表示受理。退款 unknown 保留额度，补发 unknown 保留库存与权益。事件 source_id 唯一，摘要不同拒绝；序号不连续进入补查，不倒退状态。每项动作最多一次库存 reserve/ship/release 台账。

客户可确认已解决，客服才能结案；未决动作阻止结案。结案后可重开，历史方案、批准、动作不被删除。当前权益规则保守限制累计补偿不超过原订单行金额；“补发再次破损的额外权益”和部分出库/多包裹需要下一版明确政策与数据模型。

内部索赔：draft → submitted → accepted → settled/rejected，settled 必须有结算凭证。它不改变客户工单状态。整改：调查 → 措施/观察 → 复查 → 关闭；样本阈值可配置，默认 30 为明确合成策略，不是企业效果证明。规则：编辑草稿 → 不同身份审核案例 → 发布/撤回；重叠版本冲突不可仅凭排名消除。
